# Runbook

How to set up, record, process, view and analyse. Background: the [brief](../cogmirror-brief.md), the [design](face-emotion-vectors-design.md) and the [work plan](face-emotion-vectors-workplan.md); the recorder's own notes are in `tools/recorder/README.md`.

## Two ways to run it

**1. Locally.** The recorder is a small web app you run on your laptop; takes are saved under `data/recordings/`. A watcher process picks each kept take up, tracks the face on your CPU, sends the frames to the model on Modal, and writes the time series and a Rerun recording. You view the recordings in Rerun's browser viewer served from your machine. This is the research setup: everything lands in `data/` and `results/`, and the Gate 3 analysis reads from there. Sections 2 to 4.

**2. Hosted on Modal.** The same recorder, processing and viewer links as one deployed Modal web app, behind a shared access key, so other people can record takes in a browser without installing anything. Takes land under `/public` on the Modal Volume and are processed as soon as they are kept; a status page lists every take with a view link into Rerun's hosted viewer. Section 5. Takes recorded there are pulled down to `data/` for analysis.

Both need the setup in section 1: the venv, the gemotions data, a Modal account with the `cogmirror` environment and Volume, and the model app deployed. The model itself (Gemma 4 31B) only ever runs on Modal.

## 1. Setup

Python environment and the project in editable mode, with the extras for the pipeline, viewer and analysis:

```bash
python3 -m venv .venv && .venv/bin/pip install -e ".[dev,analysis,video,viz,notebook]"
```

Add `model` to the extras to also install torch and transformers locally. That is only needed for `scripts/smoke_local.py`; the 31B model runs on Modal.

The gemotions vectors, stories and the layer-40 activation cache (about 4.5 GB) go to `data/gemotions`:

```bash
.venv/bin/python scripts/fetch_gemotions.py --cache-layers 40
```

```bash
.venv/bin/python -m pytest -q
```

Modal: authenticate once (opens a browser). All Modal commands use the `cogmirror` environment in the workspace (`--env cogmirror`), which holds the `cogmirror` Volume.

```bash
.venv/bin/modal setup
```

Copy the model weights and gemotions data to the Volume. CPU only; about 62 GB of weights plus 15 GB of caches:

```bash
.venv/bin/modal run --env cogmirror modal_app/app.py::download
```

Deploy the video pipeline once, so its containers keep the model loaded between calls (redeploy after changing anything under `src/` or `modal_app/`):

```bash
.venv/bin/modal deploy --env cogmirror modal_app/video.py
```

The story set and narration (`data/stories/stories.jsonl`, `data/stories/audio/`) are generated by `scripts/generate_stories.py`; the committed set has 70 stories.

## 2. Local: record a session

Start the recorder (it opens http://127.0.0.1:8770/ in your default browser; use Chrome or Edge):

```bash
.venv/bin/python tools/recorder/serve.py
```

In the app:

1. **Setup:** tick the four reminders (same lighting and framing as every session, camera at eye height, text at the top of the screen right under the lens, mic on). Start the camera and check it reports 1920×1080 or at least 1280×720. Choose the number of takes (12 is about 20 minutes). Leave *Allow repeats* off. The condition filter defaults to *reading only*; pick *both, interleaved* to include listening takes.
2. **Calibration:** 15 s looking at the lens with a relaxed face (its mean becomes the session baseline). For the first session, also do the scripted events here or as a separate take: neutral → smile → neutral, a yawn, a frown, noting the times (this closes Gate 2's open item).
3. **Takes:** the queue alternates stories (and conditions, if listening is on).
   - *Reading:* read the story silently first, press space, then read each sentence aloud and press space the moment you finish it.
   - *Listening* (optional): look at the lens; the narration plays one sentence at a time. Press nothing.
4. **Review:** Enter keeps the take, R marks it bad and re-queues the pair. *End session after this take* stops early.

Files land in `data/recordings/<session_id>/<take_id>.webm` with a `.json` log of per-sentence timestamps beside each. Plan at least three sessions on different days.

To list the good takes with their segments:

```bash
.venv/bin/python scripts/recordings_manifest.py
```

## 3. Local: process the takes

Recording does not trigger processing by itself. The usual way is to leave a watcher running in a second terminal during the session:

```bash
.venv/bin/python scripts/m4_run_videos.py --watch --rrd
```

It polls `data/recordings/` every 10 s and processes each take as soon as the recorder has saved it as kept (takes marked bad are never picked up): remux, face tracking locally at low CPU priority, the model on Modal, the time series. The calibration take runs first and its mean becomes the session baseline (`data/video/<session>/baseline.json`), subtracted from the other takes, so start the watcher before or during calibration. The Rerun exports wait until no take is pending, since they transcode the video. Ctrl-C stops it after finishing the exports.

With the video app deployed (section 1), `video_run.py` uses it, and its container keeps the model for 10 minutes after the last call, so takes a few minutes apart skip the model load (about $0.03 per idle minute while it waits). Without a deployment each take runs an ephemeral app and pays the load, roughly a minute of wall time; `--ephemeral` forces that, for example to test working-tree changes without redeploying.

Without `--watch` the same command processes every kept take that has no series yet and exits; use that after a session if the watcher was not running:

```bash
.venv/bin/python scripts/m4_run_videos.py --rrd
```

Outputs go to `data/video/<session>/<take>/` (frames, activation store, `<take>.parquet`), which is where `scripts/m4_agreement.py` looks, plus `data/rerun/<session>_<take>.rrd` with `--rrd`. `--force` redoes existing series; `--sessions <id>` limits it to one session; `--dry-run` prints the commands. Other options are forwarded to `scripts/video_run.py` (`--fps`, `--crop`, `--window`, ...). Cost is about $1.65 per hour of video at the default 5 fps.

A single video outside a session (a dataset clip, a stray file) goes through `scripts/video_run.py <video> --rrd` directly; that writes to `data/video/<stem>/`.

## 4. Local: view

Export every processed video and open them in the Rerun viewer, in a browser tab:

```bash
.venv/bin/python scripts/rerun_export.py --all --open
```

In the viewer:

- **Switch videos** in the *Sources* panel at the top left; each recording sits under its own `cogmirror/<session>/<take>` entry (one application id per recording, so each keeps its own default layout).
- **Scrub** with the timeline at the bottom; the video, the model's crop, the top emotions, the story (the sentence being read in bold, from the recorder's key presses) and every trace follow the cursor. Space plays, with the take's audio.
- **Traces** are overlaid on one plot on the right, with a colored legend; the *stacked* tab behind it draws them one strip each with the same y-scale (±3 reference SDs). The default set is chosen per take: valence, the PCs, the story's target emotions (drawn thicker; the story panel's header names them), and the six emotions that appear most often in the top-three labels over the clip. The blueprint panel on the left hides or shows strips. Every emotion is in the recording under `traces/emotion/`, so any can be dragged into a view.

Options: `--traces valence,pc2,happy,sad,angry` chooses the plotted traces (presets: `default`, `pcs`, `emotions`, `all`); `--y-range 4` changes the shared scale; `--take-log <take>.json` adds the sentence boundaries; `--native` opens the native Rerun app instead of the browser (it needs an `ffmpeg` executable to play the video; the browser does not); `--force` re-exports existing files.

`--open` keeps the server running until Ctrl-C. A later `--open` replaces that server with one holding every recording; refresh the tab to see them. The embedded video is transcoded small (640 px wide, a few MB per take) because the browser viewer loads every recording into memory; the model's crop is kept at full size. To open existing recordings without re-exporting:

```bash
.venv/bin/python -m rerun --serve-web data/rerun/*.rrd
```

then browse to `http://localhost:9090/?url=rerun%2Bhttp%3A%2F%2Flocalhost%3A9876%2Fproxy` (the browser viewer does not find the server on its own).

## 5. Hosted on Modal

The recorder, the processing and the viewer links also run as a Modal web app (`modal_app/web.py`), so other people can record takes in their browser without installing anything. Visitors' takes live under `/public` on the Volume, apart from the research recordings.

One-time setup: create the access key secret and upload the projection reference (the stories and narration audio are baked into the image at deploy time). The key is the only protection on the page, so pick something long; keep a copy in `data/web_access_key.txt` (git-ignored):

```bash
.venv/bin/modal secret create --env cogmirror --force cogmirror-web ACCESS_KEY="$(cat data/web_access_key.txt)"
```

```bash
.venv/bin/modal run --env cogmirror modal_app/web.py::setup
```

Deploy (and redeploy after any change under `src/`, `modal_app/web.py`, `tools/recorder/static/` or `data/stories/`); the model app must be deployed too (section 1):

```bash
.venv/bin/modal deploy --env cogmirror modal_app/web.py
```

The deploy prints the URL. Share it with `?key=<the key>` appended; the first visit sets a cookie, after which `/`, `/status` and the view links work without it. Rotating the key is `modal secret create --force` with a new value plus a redeploy. Anyone with the key can open anyone else's view links.

How it runs: each kept take is uploaded to the Volume and a Modal function processes it at once (face tracking on CPU, activations through the deployed `cogmirror-video` app, projection against the session's calibration baseline, Rerun export). A story take waits for its session's calibration take to finish first. `/status` lists every take with its stage, timings and a *view* link that opens Rerun's hosted web viewer (app.rerun.io) on that recording; `/api/status` is the same as JSON. Cost per take is a few cents of GPU plus the model container's 10 minutes of warm idle after the last take.

To put locally recorded takes on the hosted version (they are processed there like a visitor's):

```bash
.venv/bin/python scripts/web_upload.py --url <app url> --session <local session> --wait
```

To analyse takes recorded on the hosted version, pull a session's logs and series down first: `modal volume get --env cogmirror cogmirror /public/recordings/<session> data/recordings/`, and each take's `<take>.parquet` and `frames/frames.jsonl` from `/public/video/<session>/<take>/` into `data/video/<session>/<take>/` (plus `baseline.json`). The results notebook fetches face crops from the Volume on demand.

## 6. Gate 3 analysis and the results notebook

After a session is processed, the agreement analysis (reading takes only by default; `--conditions read,listen` to include listening) writes `results/m4/agreement_report.md`, `agreement_metrics.json` and `segments.parquet`; the split (held-out session and stories) is created on the first run and kept in `results/m4/split.json`, so delete that file if the set of sessions changes before the real run:

```bash
.venv/bin/python scripts/m4_agreement.py --lag-grid=-1:2:0.25
```

The plots are in `notebooks/m4_results.ipynb`; open it with `.venv/bin/jupyter lab notebooks/m4_results.ipynb` or execute it headless, which also writes the figures to `results/m4/figures/`:

```bash
.venv/bin/jupyter nbconvert --to notebook --execute --inplace notebooks/m4_results.ipynb
```

The notebook is generated from `notebooks/make_m4_results.py` so the cells stay reviewable as code; edit that file, regenerate, re-execute. Its last section clusters the frame-level emotion profiles of every take and embeds them with UMAP, with the paper's cluster names, the dominant tags and face thumbnails per cluster.

## 7. Earlier milestones (M0, M1)

Gate 0, the reproduction check against the gemotions activation caches. Uses two GPUs for a few minutes each, and writes `results/gate0_*.json`:

```bash
.venv/bin/modal run --env cogmirror modal_app/app.py::gate0
```

Image smoke test: a few images through every readout layout, plus a throughput figure. Without `--images` it uses schematic drawn faces. With it, the first image is the reference the others are compared against.

```bash
.venv/bin/modal run --env cogmirror modal_app/app.py::smoke --images neutral.jpg,smile.jpg
```

Gate 0 diagnostic: saves our story activations and reruns a subset under different numerical settings.

```bash
.venv/bin/modal run --env cogmirror modal_app/app.py::gate0diag
```

M1, static-image feasibility: data (both corpora to the Volume, face crops, the frame manifest), then the first-pass inference, baselines and analysis:

```bash
.venv/bin/modal run --env cogmirror modal_app/app.py::m1data
```

```bash
.venv/bin/modal run --env cogmirror modal_app/app.py::m1run --run pass1
```

```bash
.venv/bin/modal run --env cogmirror modal_app/app.py::m1fer
```

Then download `/acts/pass1` from the Volume to `data/acts/pass1` and run `scripts/m1_analyze.py --run pass1`. `m1noise` + `scripts/m1_noise.py` give the noise floor; `m1prompts` + `scripts/m1_prompts.py` the prompt robustness; `samples` writes a browsable gallery of clips to `data/samples/index.html`. Results and the gate tables are in the [work plan](face-emotion-vectors-workplan.md) and under `docs/results/`.
